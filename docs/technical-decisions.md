## 已确认、尚未引入的依赖

### shadcn/ui 与 Base UI

新项目明确选择 shadcn/ui 的 Base UI 版本，按需安装。官方已将 Base UI 设为新项目默认底层，Radix 仍受支持；实际初始化时仍要核对所选基础库，不仅依赖默认值。[官方说明](https://ui.shadcn.com/docs/changelog/2026-07-base-ui-default)

各层的职责是：

| 层 | 职责 | 本项目的使用方式 |
| --- | --- | --- |
| Base UI | 提供底层交互与无障碍能力，例如弹窗焦点管理 | 保留其正确行为，不为外观重写基础交互 |
| shadcn/ui | 提供进入项目源码、可以维护的组件及样式组织 | 优先使用现成组件和变体，必要时组合 |
| Tailwind 与设计变量 | 定义组件在本项目中的外观 | 通过语义变量、已有变体与局部布局控制样式 |
| 业务组件 | 表达文章条目、作品信息等业务内容 | 在出现实际复用需求时组合，不预建通用框架 |

不是每个 shadcn 组件都必须调用 Base UI 原语。具体依赖以选定版本的官方组件实现为准，不为了名称一致替换其内部实现。

使用顺序固定为“已有 shadcn 组件 → 组合已有组件 → 解释缺口后自定义”。段落、标题、链接和布局继续使用语义化 HTML，不为统一形式额外包装无必要的组件。

检查方法：确认组件来源和基础库；比较已有变体是否满足需求；修改后检查键盘、焦点、状态和样式，不能只检查截图。

### Motion 与 GSAP

业务动效默认使用 Motion for React。当前尚未安装。GSAP 只在出现明确的复杂时间线、滚动联动或精细编排需求后单独评估，不提前加入依赖。[Motion 官方文档](https://motion.dev/docs/react)

保留组件自带的基本状态过渡。同一元素的同一属性由一个动画机制控制。动效必须能被打断，不能依赖播放完毕才能操作。具体规范见[动效与无障碍](./design-system.md#8-动效规范)。

### 数据请求与状态

初期使用 Next.js 与原生 `fetch`，组件内交互使用 React 自身状态能力。暂不引入全局状态库、额外请求缓存库或新的接口代理层。

数据缓存规则在首次接入真实读取接口时单独学习和确认。不能把鉴权内容按公开内容缓存。接口字段、枚举、分页和错误格式以 Mix Space 当前源码及文档为准，缺失时先明确问题，不猜测 DTO。

## Spectrum 的使用边界

参考 Spectrum 的原则、设计变量、排版层级、布局和组件使用指导。网站视觉由用户设计，不引入 Adobe 的组件库，不复制 Adobe 字体或品牌色，也不把企业工具的全部组件范围搬进博客。[Spectrum](https://spectrum.adobe.com/)

本项目的三层变量结构是自己的组织方式，不声称与 Spectrum 内部数据格式完全一致。具体映射遵循 shadcn 的主题变量约定。[shadcn 主题说明](https://ui.shadcn.com/docs/theming)

## 依赖与变更规则

- 现有依赖、标准能力和已选组件能解决时，不增加新包。
- 引入依赖前先说明实际需求、职责、替代方案和维护影响，再在用户确认的学习单元中实施。
- 安装时记录实际版本并更新对应锁文件，不因示例使用 `latest` 就长期依赖浮动版本。
- 两个项目保留各自的 pnpm 版本和锁文件，不复制或链接依赖目录，不改造为新的 monorepo。
- 本次只建立文档，不安装 shadcn/ui、Base UI、Motion 或 GSAP，不启动服务、不生成页面。
