# SinPersonalSpace 项目文档

更新日期：2026-10-22。当前阶段：三栏布局骨架已实现，设计系统 v0.1 待视觉评审，分类与关于页面导航已接入公开接口，文章列表与分类筛选已实现，文章详情已接入 Markdown 阅读，Plate 富文本尚在计划阶段。

本项目是使用现有 Mix Space 后端的新前端，也是逐步学习 Next.js、组件和设计系统的实践项目。现有 Shiro 前端保留，不迁移此前的设计原型。

## 三种状态必须分清

| 状态 | 当前内容 | 含义 |
| --- | --- | --- |
| 已确认决策 | Next.js、React、TypeScript、Tailwind CSS；直接使用 Base UI，自行设计样式；Motion；复用 Mix Space 与 mx-admin | shadcn/ui 仅作为按需选用或参考的来源；这些选择不代表依赖已经安装或功能已经实现 |
| 待评审基线 | 中性色、字号、间距、尺寸、圆角和动效时长 | 是设计系统首版建议，不是最终视觉；品牌色和页面版式由用户决定 |

当前已替换欢迎页：左侧文字导航、中间页面内容、右侧补充信息占位。桌面通过 react-resizable-panels 拖动两条分隔线调整栏宽，不记忆宽度、不折叠；窄屏保留 CSS Grid，隐藏右栏，手机导航置顶。`pnpm dev` 已联合启动本仓库前端、Core 与共享 MongoDB/Redis，不启动管理后台。颜色跟随系统，尚未完整应用设计系统 v0.1。

## 学习与实施顺序

每个单元按“讲清楚概念与取舍 → 用户确认这一小步 → 最小改动 → 验证与回顾”推进。用户已经明确授权的同一事项不重复询问；完成一个单元不自动扩展到整站开发。

| 单元 | 学习重点 | 完成标志 |
| --- | --- | --- |
| 1. 文档与边界 | 区分技术决策、设计建议和运行事实 | 本目录四份文档、项目入口说明与文档检查完成 |
| 2. 颜色语义与排版 | 理解基础值、语义变量、中文阅读尺度 | 一起评审对应规范，记录接受或调整的决定，不生成页面 |
| 3. 本地启动 | 理解进程、端口、环境变量和资源归属 | 已实现 workspace 联合启动，理解共享数据与进程归属 |
| 4. 第一个组件 | 理解 Base UI 的交互基础，以及自己定义的样式变量和状态外观 | 只安装必要依赖，完成一个 Button 示例及其检查 |
| 5. 逐步组合与接入 | 将已有组件用于用户设计的局部 | 每次完成一个局部，再核对实际接口后接入数据 |

首期范围是公开文章、手记、作品、导航、搜索、主题和阅读体验。评论、访客登录与在线编辑后置，内容管理继续使用旧管理后台。

## 文档与变更维护

- 每次修改规范，记录日期、改了什么、为什么改，以及是建议还是已确认决定。
- 某个功能真正落地后，再同步更新技术决策和本地开发文档中的状态。
- 小范围变更验证后独立提交，使用 Conventional Commits，描述使用中文。提交不代表获得推送或部署授权。
- 不把旧设计原型、检索工具建议或第三方组件默认值直接当成用户批准的设计。

## 首次文档交付验收（历史范围）

- 四份文档的相对链接能解析，术语和端口一致。
- 设计规范包含用途、原因和检查方法，颜色配对可复算。
- “计划命令”没有被写成当前可执行功能。
- Git 差异仅包括本目录和 `AGENTS.md` 的入口说明，Next 自动生成区块保留。
- 不安装依赖、不生成 UI、不运行应用构建或服务。文档完成不触发后续单元。
