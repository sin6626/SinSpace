# 碎碎念独立模块计划

状态：已完成第一版（2026-10-29），提交 3098cd1（Core）、58a6f00（SDK）、a640929（迁移）、23ac965（后台）、1e8e8a5（前台）。

用户确认的决定：碎碎念不要赞踩和评论（“不喜欢说闲话有人拉踩”）；不拆“名词/解释”字段，就是闲话；后台“速记”改名“思考”；思考在前台挪进“更多”；后台菜单放在“说说”和“思考”中间；后台页面不必照一言的样子，可以自由设计。

和计划的出入：
- 后台编辑时文字与图片分开：文本框只放文字，图片排在下面拖角缩放，保存时按顺序接在文字后面（不在文本框里露出图片 Markdown）。正文里夹在文字中间的图，编辑保存后会挪到文字后面。
- 迁移靠“正文 + 时间都相同”判断已迁移，没有在新文档里记原 id。
- 后台仪表盘没有加碎碎念的统计卡片（Core 的统计接口没有碎碎念数量）。
- 前台没有做“刚写了一条碎碎念”的访客提示（Core 没给 MURMUR 事件加访客广播）。

现状：本地 24 条旧速记已复制成碎碎念，旧速记原样保留，删不删由站长在后台决定。另有一条“测试碎碎念（可删除）”和图床 dev/ 下一张测试图，留给站长核对后在后台删除。本地 Webhook 已勾好 28 个事件。

## 为什么分出来

三类内容不一样：

| | 一言（说说） | 思考（速记，Core 的 recently） | 碎碎念（新） |
|---|---|---|---|
| 写什么 | 摘一句别人的话 | 引用网站/书/歌（OG 卡片）+ 自己的看法 | 问 AI 时遇到的新词，用自己的话讲出来；偶尔一句随口的话 |
| 字段 | 句子、作者、出处 | 正文、卡片类型与元数据、引用站内文章 | 正文（Markdown，可带图） |

本地 24 条速记全是纯文字，没有一条卡片，基本都是碎碎念。现在前台 /thinking 叫“碎碎念”，读的却是速记，以后写带卡片的思考会混进去。

## 命名

- Core：模型 `MurmurModel`，集合 `murmurs`，接口 `/murmurs`，事件 `MURMUR_CREATE / MURMUR_UPDATE / MURMUR_DELETE`（BaseCrudFactory 按模型名自动生成）。
- 前台：`/murmurs`，导航“碎碎念”指向这里。
- 速记回到 Innei 原意，前后台都叫“思考”：后台菜单“速记”改名“思考”，前台 /thinking 标题改“思考”，从一级导航挪进“更多”。

## 步骤（每步单独提交）

### 1. Core：新模块
- `apps/core/src/modules/murmur/`：照一言（say）的写法用 `BaseCrudFactory`，公开读列表（分页、按时间倒序）和单条，写入需登录。
- 字段：`content`（Markdown，必填）、`created`、`modified`。
- `business-event.constant.ts` 加三个事件，后台 Webhook 勾选列表会自动出现，同时推给访客的 WebSocket（前台以后可做“刚写了一条碎碎念”的提示，这版不做）。
- 图片引用登记：`FileReferenceType` 加 `murmur`，新建/修改时 `updateReferencesForDocument`、删除时 `removeReferencesForDocument`，否则粘贴的图一小时后会被清理任务删掉。
- 首页“最近发生的事”（Core `/activity/recent`）里“写了一条碎碎念”目前读的是速记，改为读 murmurs（思考保留为“写了一条思考”）。
- 检查：`scripts/verify-core-murmur.mjs`（字段校验、图片引用登记与删除时解除）。

### 2. SDK
- `packages/api-client` 加 `MurmurController` 与模型类型，前台 `lib/api.ts` 注册（不注册会是 undefined，只表现为“读取失败”）。

### 3. 迁移现有 24 条
- `scripts/migrate-murmurs.mjs`：从速记读出纯文字的条目，按原创建时间写进 murmurs，**只复制不删除**；重复运行不会重复写（按原 id 记录在新文档里）。
- 先跑本地，你在后台核对。线上等部署时再跑，用你自己建的线上令牌（和 `pnpm draft --prod` 一样）。
- 旧速记里的这 24 条，确认无误后由你决定删不删（删除是不可恢复操作，我不自动做）。
- 速记上已有的赞/踩、评论不迁移（碎碎念第一版没有这两样，见下方“待你确认”）。

### 4. 后台：碎碎念菜单
- 侧栏新增“碎碎念”（在“思考”上面），列表页照一言列表的写法：时间、正文预览、编辑、删除，按时间倒序分页。
- 新建/编辑弹窗：
  - 文本框 + ⌘V 粘贴图片：复用 Markdown 编辑器的上传逻辑（`editor-store.ts` 的 `uploadImageFile`），先插 `![上传中...]` 占位，传到图床后换成真实地址。
  - 文本框下方是图片预览区，每张图带四个角柄，按原比例拖动缩放，显示当前百分比，松手写回 Markdown：`![](地址 "w=40%")`。宽度记在标题里而不是地址后面，Core 才能对上图片地址。
- 沿用后台现有 Naive UI 风格。
- 检查：在本地后台实际粘贴一张测试图（写一条测试碎碎念、往图床 `dev/` 传一张图，留给你核对后删除）。

### 5. 前台
- `/murmurs` 列表（组件 `components/murmur-list.tsx`，数据 `getMurmurs`，标签 `blog:murmurs`，Webhook 加 `MURMUR → blog:murmurs` 并同步 `scripts/verify-webhook.mjs`，后台 Webhook 需多勾 3 个事件）。
- 正文按 Markdown 渲染，图片读标题里的 `w=40%` 设宽度，最宽不超过卡片，只放行 http(s)。
- 首页“屋里”的碎碎念块改读 murmurs；有图时文字下面放一排小缩略图。
- /thinking 改名“思考”、挪进“更多”；sitemap 加 /murmurs。
- `/debug` 加碎碎念卡片示例（含不同宽度的图）。
- 检查：e2e `scripts/e2e/murmurs.mjs`（列表能打开、图片宽度按百分比、首页缩略图），`dev-issues.mjs` 加入 /murmurs。

### 6. 收尾
- 更新 AGENTS.md、docs/recently-plan.md（速记即“思考”）、docs/webhook-local.md（事件数）。
